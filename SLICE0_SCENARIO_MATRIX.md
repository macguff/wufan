## Slice 0 exit gaps

- Runtime random exploration uses 16 × 1,000 fixed events plus an optional fresh CI nightly seed; it asserts coverage of every Event variant, result class, and result outcome. A 32-case `proptest` generates 1,000–1,256-event Runtime traces, checks S1–S3 and the forbidden failed-state combinations after every prefix, and verifies trace decode/replay; the same inputs also run through the fake scheduler and check Applied/journal agreement and unique ApplyHostCommit identities. Deployment and Memory models run seeded 32 × 1,000 fault/merge interleavings; deployment checks phase-local D6 invariants after each action. Failures shrink through proptest or the runtime trace shrinker.
- Matching Rust 1.91.1 `llvm-tools-preview` coverage runs locally. Combining the harness and RuntimeCore test binaries reports 93.53% region and 96.47% line coverage across core/models (RuntimeCore: 94.83% region, 97.31% line); 80 instrumented tests passed. Local `xtask ci` and nextest passed all 80 tests. With the pinned `-Z coverage-options=branch` flag enabled for coverage runs, LLVM reports 271/364 branches (74.45%) in the RuntimeCore file. This file-level figure includes helpers and tests. The source-location reducer audit covers 182/200 directions; the remaining 18 are reviewed as unreachable under the structural invariant or an earlier guard. The local audit passes and CI now publishes the branch report, audit, and coverage JSON; the Slice 0 commit de7b912 passed remote core, coverage, and Windows/MSVC CI, and both coverage and probe artifacts were published.
- I2/I4/I5/I6 have a combined cross-model oracle. Proptest varies commit outcomes, verifies duplicate intent/result non-reapplication, Applied ACK/journal consistency, and mutates all six commit identity fields to verify I3 rejection before host mutation. `fake_scheduler_covers_every_terminal_effect_result` drives all four result classes through success/reject/indeterminate; commit indeterminate is tested before and after a host write. Deterministic regressions cover Broker disconnect during a pending composition start, late success/cancel, focus switching during an Applying commit, duplicate EngineUpdate while a composition effect is pending and EngineUpdate during an Applying commit, and stale or out-of-range candidate/UI intents. S2/S3 oracles reject malformed batches and replies. Minimized reducer-panic traces are persisted and CI uploads them on failure. The reducer return-site gate and reviewed branch audit are present; the Slice 0 coverage artifact was published by the remote CI run.
- S1–S3 plus focus/session/composition/mode consistency are checked by the reducer assertions and every generated trace prefix. `deterministic_scenarios_cover_every_transition_return_site` captures calls to the production `TransitionResult` constructors and asserts that deterministic scenarios reach every source return site. The LLVM branch report now quantifies the remaining boolean paths; the return-site gate does not substitute for them. No failure trace was produced by the passing local run, so a passing run cannot exercise the failure-artifact upload path.
- I1, actual COM edit-session behavior, OS-level authentication, sanitizer/process-kill behavior, and all Windows-native evidence remain open integration gates.
